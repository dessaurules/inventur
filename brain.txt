# brain.txt — Kontext für LLM (z. B. Claude Code): Projekt „vibe-inventur“

Diese Datei beschreibt Aufbau, Verhalten, Design, Abhängigkeiten, Ports, Umgebungsvariablen und typische Fallstricke. Sie ergänzt README.md und pocketbase/ANLEITUNG_*.md.

---

## 1. Zweck

Web-App für **Inventur / Zählen**: Artikelstammdaten (PocketBase), Zählsessions, laufende Zählungen, Archiv abgeschlossener Inventuren. **Login und Nutzerverwaltung** über PocketBase (Auth-Collection `users`). Rollen steuern Magazin-Lesen/Schreiben, Inventur-Zählen, Admin-Funktionen.

---

## 2. Technologie-Stack

| Schicht | Technologie |
|---------|-------------|
| Frontend | React 19, Vite 7, Tailwind CSS 4 (`@tailwindcss/vite`), lucide-react, cmdk (Befehlspalette Magazin), Radix UI (Dialog, Checkbox, …) |
| Backend (BFF) | Node.js, Express 5 (`server.mjs`, ES modules `type: module`) |
| Datenbank / Auth | **PocketBase** (eigenständige Go-Binary, nicht nur npm-Paket `pocketbase` für Client) |
| Barcode | `@zxing/browser` + optional `BarcodeDetector` (Kamera; **Secure Context**: HTTPS oder localhost) |
| Export / PDF | jspdf, jspdf-autotable, xlsx |
| Mail (Einladungen) | nodemailer (Express); PocketBase kann zusätzlich eigenes SMTP für Verifikation/Reset |
| UI Magazin | `@tanstack/react-virtual`, `@dnd-kit/*` (Kategorien sortieren), sonner (Toasts) |

## 4. Zwei Frontend-Einstiege (MPA)

| Datei | data-vibe-entry | countingApp | Nutzung |
|-------|-----------------|-------------|---------|
| index.html | counting | true | **Zähler-App**: Inventur, Zählsession, Touch-UI, PWA |
| backend.html | backend | false | **Desktop-Backend**: Magazin, Lager, Mitarbeiter, Inventur-Archiv-Liste |

`resolveCountingEntryUi()` in `App.jsx`: UI-Elemente mit `countingEntryUi` nur bei `data-vibe-entry="counting"` (Header-Suche, Kategorien, Session-Leiste, Inventur-Stack).

**Navigation:**
- Zähler-App: nur „Inventuren“ (+ Account im Einstellungs-Menü); kein Magazin/Lager in der Seitenleiste.
- Backend: Inventuren, Lagerverwaltung, Magazin, Mitarbeiter (je nach Rolle).

## 6. Verhalten (kurz)

### Auth & PocketBase-URL
- Wie bisher: `VITE_POCKETBASE_URL` → direkter PB-Zugriff (CORS); sonst `origin + '/api/pb'` über Express.

### Zähler-App (index.html) — aktive Inventur-Session

| Feature | Dateien / Hinweis |
|---------|-------------------|
| Artikelliste | `ArticleView.jsx`, Filter Kategorie + Suche |
| Kategorie-Wechsel | Scroll der Liste nach oben (`window.scrollTo`) |
| **Suche** | Filter Name/Nr./Barcode; Platzhalter nur „Artikel suchen“ |
| **Barcode in Suche** | Icon im Suchfeld → `InventurBarcodeScanOverlay`; Hardware-Scanner: 8–20 Ziffern + 160ms Debounce → `barcodeSearchResolve.js` |
| Bekannter Barcode | `handleBarcodeArticleFound` → Kategorie „Alle“, Scroll zur Zeile |
| Unbekannter Barcode | Gelbes Banner unter Toolbar + „Artikel hinzufügen“ |
| **+ Button** | `BarcodeScanDialog` Titel „Artikel hinzufügen“: Formular primär; Kamera eingeklappt, Scan-Icon am Barcode-Feld |
| Session | Start/Fertig in `session-count-bar`; `sessionStorage` Key `vibe-inventur-zaehl-session-id` |
| **Befehlspalette** | `CountingCommandPalette.jsx`, Side-Menü „Suche & Aktionen“, **⌘K** und **/** (nur mit `inventur`-Rolle) |

### Backend — Magazin (`view === 'admin'`)

- Lazy: `MagazinPage` → `magazin-shell.jsx`.
- **Befehlspalette** (`command-palette.jsx`): ⌘K, `/`, Aktionen Neu/Excel/Export(Platzhalter), Artikel- & Kategorie-Suche.
- **Artikelliste:** Sortierung per Spaltenkopf (Nr., Name, Preis, Einh.) + Dropdown; Logik `article-list-sort.js`.
- Detail-Drawer: Feld **Artikelnummer** (sync mit `lieferanten_artnr` beim Speichern).
- PDF-Rechnung: `POST /api/magazin/parse-invoice-pdf` (Express).

### Backend — Inventur ohne Zähler-UI

- `LastInventurView.jsx`: abgeschlossene/laufende Sessions, Export CSV/PDF, Admin-Aktionen.
- Kein `ArticleView` / keine Session-Leiste wie in der Zähler-App.

### Performance (Login / Magazin)

- Artikelkatalog nur bei Bedarf (`needsArticleCatalog` in `App.jsx`).
- Inventur-Session-Listen: ein Fetch (`loadInventurSessionLists`).
- `React.lazy`: Magazin, Lager, Mitarbeiter; ZXing dynamisch importiert.

### Barcode allgemein

- Abgleich: `barcodesMatch` (Trim, optional nur Ziffern).
- Open Food Facts optional: `/api/openfoodfacts/product/...` (über Express-Proxy in Dev).

## 9. Installation / Dev-Start

1. Node.js, `npm install`, PocketBase-Binary in `pocketbase-bin/`.
2. `.env` aus `env.example`.
3. `npm run pb` (Migrationen + serve).
4. Dev:
   - **A:** `VITE_POCKETBASE_URL` + `npm run dev` (nur Vite :5173).
   - **B:** `POCKETBASE_URL` + Admin-Creds, `npm run server` (:3000) + `npm run dev` (Proxy `/api`).
   - **Voll:** `npm run dev:full` (PB + Vite + Express parallel).
   - **Neustart:** `npm run dev:restart` — beendet Ports 8090/5173/3000, startet Stack neu (`scripts/restart-dev-stack.sh`).

## 16. Typische Probleme

- **Keine Artikel / 403:** PB Rules, falsche DB (`--dir`), Migrationen.
- **`/api/pb` Fehler:** `npm run server` fehlt (Variante B).
- **CORS:** Origin in PB erlauben (Variante A).
- **Kamera:** Nur HTTPS oder localhost; LAN oft `certs/` + `HTTPS_*` in `.env`.
- **Einladung localhost:** `APP_PUBLIC_URL` setzen.
- **Magazin Export:** Palette zeigt Platzhalter-Toast — noch nicht angebunden.
- **Listen-Filter Magazin:** Toolbar-Button „Filter“ disabled (Platzhalter).
- **PB nach Neustart leer:** Falscher `--dir` oder andere `pb_data`-Instanz.
- **Ports belegt:** `npm run dev:restart` oder manuell 8090/5173/3000 freigeben.
