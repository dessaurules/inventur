# brain.txt — Kontext für LLM (z. B. Claude Code): Projekt „vibe-inventur“

Diese Datei beschreibt Aufbau, Verhalten, Design, Abhängigkeiten, Ports, Umgebungsvariablen und typische Fallstricke. Sie ergänzt README.md und pocketbase/ANLEITUNG_*.md.

---

## 1. Zweck

Web-App für **Inventur / Zählen**: Artikelstammdaten (PocketBase), Zählsessions, laufende Zählungen, Archiv abgeschlossener Inventuren. **Login und Nutzerverwaltung** über PocketBase (Auth-Collection `users`). Rollen steuern Magazin-Lesen/Schreiben, Inventur-Zählen, Admin-Funktionen.

---

## 2. Technologie-Stack

| Schicht | Technologie |
|---------|-------------|
| Frontend | React 19, Vite 7, Tailwind CSS 4 (`@tailwindcss/vite`), lucide-react (Icons) |
| Backend (BFF) | Node.js, Express 5 (`server.mjs`, ES modules `type: module`) |
| Datenbank / Auth | **PocketBase** (eigenständige Go-Binary, nicht nur npm-Paket `pocketbase` für Client) |
| Barcode | `@zxing/browser` (Kamera-Scan; braucht Secure Context: HTTPS oder localhost) |
| Export / PDF | jspdf, jspdf-autotable, xlsx |
| Mail (Einladungen) | nodemailer (Express); PocketBase kann zusätzlich eigenes SMTP für Verifikation/Reset |

## 6. Verhalten (kurz)

- **Auth:** PocketBase `pb.authStore`; nach Login je Rolle unterschiedliche Views (Dashboard Zählen, Magazin/Artikel, Lagerverwaltung, Admin, Mitarbeiter, E-Mail-SMTP-Einstellungen, Account).
- **PocketBase-URL:** Wenn `VITE_POCKETBASE_URL` gesetzt → Browser spricht **direkt** mit PocketBase (CORS in PB nötig). Wenn **nicht** gesetzt → Basis-URL ist `window.location.origin + '/api/pb'` → **Express muss laufen** und proxyt zu `POCKETBASE_URL` (Produktion: ein Host).
- **Barcode:** ZXing über Video; Abgleich mit Trim und optional nur-Ziffern (`barcodesMatch`). Optional Produktname von **Open Food Facts** (`https://world.openfoodfacts.org/api/v2/product/...`).
- **Zählsession:** sessionStorage-Key `vibe-inventur-zaehl-session-id`; Archivierung in `inventur_archiv`; Live-Zählen in `zaehlung_aktuell` verknüpft mit `zaehl_sessions`.
- **Express-Zusatz-APIs (nicht von PocketBase):** z. B. `/api/invite/send`, `/api/invite/accept`, `/api/users`, `/api/mail-settings`, `/api/health` — benötigen oft Superuser-Token serverseitig (`POCKETBASE_ADMIN_*`).

## 7. Rollen (PocketBase `users`)

Siehe `src/lib/userCapabilities.js` und Migrationen (z. B. `1775500000_users_roles_tenant_rules.js`, `1777130000_users_role_select_all_app_roles.js`).

- **admin:** voller Zugriff inkl. `manageUsers`

- **inventur:** Inventur ja, Magazin nur lesen
- **magazin_readonly:** nur Magazin lesen
- **Legacy:** `users` wird wie inventur behandelt; `is_admin` und `permissions.manageUsers` können Admin-Rechte erweitern

## 8. PocketBase: Migrationen und Datenpfad

- Migrationen liegen in **`pb_migrations/`**. PocketBase startet mit **`--dir`** (Datenbank) und **`--migrationsDir`** (dieser Ordner).
- **Kritischer Fehler:** PocketBase **ohne** `--dir ./pb_data` vom „falschen“ CWD zu starten legt/leert eine andere DB (z. B. unter `pocketbase-bin/pb_data`). Immer explizit **`--dir ./pb_data`** zum **gewünschten** Datenordner oder `npm run pb` aus Projektroot nutzen.
- Collections (Standardnamen): `users`, `user_invites`, `artikel`, `zaehl_sessions`, `zaehlung_aktuell`, `inventur_archiv`, `standorte`, `lager`, `unterlager`, `user_unterlager` — siehe `pocketbaseCollections.js` und `ANLEITUNG_COLLECTIONS.md`.
- **`pocketbase-bin`:** Repo kann `pb.zip` haben; für Betrieb die **passende PocketBase-Binary** für OS/Arch (Linux amd64/arm64, macOS, …) von pocketbase.io verwenden und ausführbar machen. `package.json` Script `pb` erwartet `./pocketbase-bin/pocketbase`.

## 9. Zusätzliche Software — Installationsreihenfolge

1. **Node.js** (LTS, npm funktionsfähig) — für `npm install` / `npm ci`.
2. Im Projektroot: **`npm install`** (oder `npm ci` bei Lockfile). Auf dem Zielserver **immer** installieren; `node_modules` von anderem OS nicht kopieren (native Module z. B. Tailwind Oxide).
3. **PocketBase-Binary** beschaffen, in `pocketbase-bin/pocketbase` (oder Pfade in Scripts anpassen), `chmod +x`.
4. **`.env`** aus `env.example` ableiten (siehe Abschnitt 11).
5. PocketBase starten: **`npm run pb`** (oder gleichwertiger `serve` mit `--dir` und `--migrationsDir`).
6. Erstes Mal: PocketBase Admin unter `http://127.0.0.1:8090/_/` — Superuser anlegen falls leer.
7. Entwicklung:
   - **Variante A:** `.env` mit `VITE_POCKETBASE_URL=http://127.0.0.1:8090` + CORS in PB für `http://localhost:5173` → nur **`npm run dev`**
   - **Variante B:** `POCKETBASE_URL` + Admin-Creds in `.env`, **kein** `VITE_POCKETBASE_URL` → **`npm run server`** (Port 3000) **und** **`npm run dev`** (Port 5173; Vite proxyt `/api` → 3000)
8. Produktion: **`npm run build`** dann **`node server.mjs`** oder **`npm start`** (build + server). PocketBase muss separat laufen (oder anderer Host, dann `POCKETBASE_URL` anpassen).

Optional Produktion: Reverse Proxy (Nginx/Caddy) für TLS auf Port 443 → Proxy zu Node `PORT` (default 3000); PocketBase nur intern (127.0.0.1:8090).

## 11. Umgebungsvariablen (Überblick)

Vollständige Kommentare: **`env.example`**. Wichtigste:

**Express / PocketBase (Backend):**
- `POCKETBASE_URL` — Basis-URL ohne trailing slash (z. B. `http://127.0.0.1:8090`)
- `POCKETBASE_ADMIN_EMAIL`, `POCKETBASE_ADMIN_PASSWORD` — Superuser für Server-APIs und Bootstrap
- `POCKETBASE_USERS_COLLECTION`, `POCKETBASE_INVITES_COLLECTION` — optional, Defaults `users`, `user_invites`
- `PORT` — Express
- `HTTPS_KEY`, `HTTPS_CERT` oder Dateien unter `certs/` — optional TLS direkt in Node (Smartphone-Kamera im LAN)
- `APP_PUBLIC_URL` — öffentliche URL für Einladungslinks (Produktion)
- `APP_NAME` — Anzeigename in Mails
- SMTP: `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` — oder nur `SMTP_PASS` wenn PB SMTP aktiv (siehe server.mjs)
- `TENANT_BOOTSTRAP_ON_START` und weitere `BOOTSTRAP_*` / `DEFAULT_*` — siehe `env.example` und `lib/tenantBootstrap.mjs`

**Vite (nur zur Build-Zeit / Dev):**
- `VITE_POCKETBASE_URL` — direkter PB-Zugriff vom Browser
- `VITE_POCKETBASE_*_COLLECTION` — Collection-Namen überschreiben

Nach Änderung an `VITE_*`: Dev-Server neu starten; für Produktions-Build: `npm run build` erneut.

- **Nicht committen:** `.env`, `data/mail-settings.json` (kann SMTP-Passwort), `certs/*.pem`, `pb_data/` (je nach Team-Policy; enthält DB + Dateien), `node_modules`, `dist`.

## 16. Typische Probleme (für Debugging)

- **Keine Artikel / 403:** PocketBase API Rules oder falsche Collection-Namen; Migrationen fehlen oder falsche DB (`--dir`).
- **`/api/pb` Netzwerkfehler in Dev:** Variante B ohne laufenden `npm run server`.
- **CORS in Dev Variante A:** Origin in PocketBase erlauben.
- **Kamera geht nicht:** Nur HTTPS oder localhost; öffentlich HTTP blockiert oft getUserMedia.
- **Einladungslink zeigt localhost:** `APP_PUBLIC_URL` in Produktion setzen.
- **Rollen-PATCH fehlgeschlagen:** Select-Feld `role` in PB muss alle App-Werte kennen (Migration `1777130000`).
